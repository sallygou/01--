# 88-工具箱

稳定性机制的落地位置：确定性校验脚本 + Git Hook。**零第三方依赖**（本机无 PyYAML，脚本内置轻量 YAML 解析）。

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `validate.py` | 协作规则校验器（结构校验，不判断业务方案对错） |
| `pre-commit` | Git pre-commit Hook 源码；安装到各仓 `.git/hooks/pre-commit` 后生效 |

## 校验脚本用法

```bash
# 校验指定文件
python 88-工具箱/validate.py 文件1.md 文件2.md

# 校验三个仓库全部 Markdown
python 88-工具箱/validate.py --all

# 从标准输入读取文件列表（Hook 使用的方式，兼容中文/空格路径）
printf '%s\n' "文件.md" | python 88-工具箱/validate.py --stdin
```

退出码：`0` 无错误；`1` 存在错误（Hook 据此阻止提交）。

## 已实现的检查项

| 编号 | 检查项 |
| --- | --- |
| R1 | YAML 格式合法（分隔符、缩进、重复字段、未知行） |
| R2 | 必填字段缺失（含日期格式） |
| R3 | 文档类型合法、编号前缀与类型一致 |
| R4 | 任务状态取值合法、单据编号格式合法 |
| R5 | 编号重复（允许"交换区原件 + 个人仓 01-输入 副本"成对） |
| R6 | 发起人/接收人/负责人/作者/审核人在成员名册中，且发起人 ≠ 接收人 |
| R7 | 关联任务存在、关联文件路径存在、回执/退回指向的协同单存在 |
| R8 | 文件所在目录符合协作规则 |
| R9 | 正式知识区发布红线（审核人/审核结论/审核记录三者齐全） |

模板文件（`*-模板.md`）只校验 YAML 格式与类型，占位值不参与必填判定。

## Hook 安装

```bash
cp 88-工具箱/pre-commit <目标仓库>/.git/hooks/pre-commit && chmod +x <目标仓库>/.git/hooks/pre-commit
```

触发时机：`git commit` 且本次暂存区含 `.md` 文件。
失败时**只阻止提交**，不删除/覆盖任何文件，可用 `git commit --no-verify` 绕过（不推荐）。

> 局限：`.git/hooks` 不随 Git 传播，成员需各自安装；集中校验需依赖 CI（GitHub Actions + 受保护分支）。
