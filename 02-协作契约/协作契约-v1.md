# 协作契约 v1（早鸟票活动平台）

本契约是团队协作的最高规则，所有成员及其 Agent 必须遵守。修改契约须经两人以上确认。

## 2. 仓库边界

- 公共仓存放团队共识、任务流转与知识沉淀；两个个人仓各自独立、互不直接修改。
- 任何跨成员传递必须经过公共仓 `04-交换区/`，且必须附带单据。
- 个人仓内未经确认的产出不得放入公共仓。

## 3. 三种单据

单据一律为 Markdown 文件，顶部使用 YAML 结构化字段，模板见 `单据模板/`。

| 单据 | 用途 | 发起方向 |
| --- | --- | --- |
| 协同单 | 发起协作：把任务包交给对方 | 委托方 → 受托方 |
| 回执单 | 确认收到并反馈进度/结果 | 受托方 → 委托方 |
| 退回单 | 退回不符合要求的任务包或产出 | 收到方 → 发起方 |

单据编号规则：`单据类型-日期-序号`，如 `协同单-20261029-001`。

## 4. 六件式任务包

每个任务以"任务包目录"为单位流转，包含六个部分（模板见 `任务包模板/`）：

1. 任务说明（背景、目标、范围）
2. 输入清单（依赖资料与接口）
3. 执行计划（步骤、分工、时间）
4. 产出清单（交付物与验收标准）
5. 协作记录（协同单/回执单/退回单的流转记录）
6. 沉淀归档（成果去向、知识沉淀计划）

## 5. 知识区规则

- 知识区分为**静态知识**（稳定不变的规范、背景资料）与**动态知识**（持续更新的成果归集）。
- 动态知识按 `current/`（当前有效版本）与 `history/`（历史版本）存放。
- **个人产出未经审核不得直接成为正式公共知识**：须先经协作流转或他人确认，再由管理员放入知识区。
